# Offline resource manifest and experiment protocol

`outcome_eval.py validate-spec --root <directory> --spec <relative.json>` reads at most 64 KiB of regular UTF-8 JSON, without symlinks, duplicate keys, subprocesses, oracle calls or network. See `experiment-spec-example.json`. This validates declarations, not a frozen outcome plan, receipt, execution, evaluator independence or approval. Frozen assignments name every holdout task in both balanced orders. Full planned attempts, including failures, aborted, missing and unknown, remain in the denominator. Coverage includes lead, worker, review, integration and retries; missing measurement is unknown, not zero. Metrics separately include wall time, quality and user burden. Execution, resource and measurement approval gates must be declared; declarations do not grant approval. Existing `all_success_k` is not pass@k. The October 28, 2026 #3 run was stopped and is not a success.

Resource manifest JSON uses `format: company-resource-manifest/v1` and a `resources` array. Each entry has exactly `service`, `approval_ref` (nonsecret identifier, not an approval credential), `auth` (`authenticated`, `unauthenticated`, `unknown`), `hosts`, `models`, `efforts`, `tools` (nonempty allowed identifier arrays), `billing` (`subscription`, `paid_api`, `unknown`), `quota` (`available`, `exhausted`, `unknown`), `spending_ceiling` (nonnegative amount or null), `observed_at`, `valid_until` (UTC `YYYY-MM-DDTHH:MM:SSZ`). Entries have unique services. Unknown keys, including secret fields, are refused. Never place credentials in any field. References are identifiers, not dereferenced and not verified. A paid declaration needs explicit config `api_paid` plus a caller-supplied spend bound within ceiling; amounts must use the same externally agreed units. This is a bound, not proof of balance or actual cost.

Launcher integration API: `company_config.resource_manifest_check(config, root=Path(...), name='relative.json', required=True, service='codex', host='host-id', model='model-id', effort='high', tools=['local-read'], billing='subscription', spend=None)` returns `status` (`declared_ready`, `denied`, or `unknown`), `errors`, and `basis`. Only `declared_ready` allows the explicitly opted-in manifest gate; separately retain existing prelaunch checks. A missing optional name returns unknown and leaves legacy readiness behavior intact. Missing required, invalid, stale/future, mismatched, unknown or unauthorized declarations deny. `readiness(..., manifest_root=..., manifest_name=..., manifest_required=..., manifest_scope={host,model,effort,tools,billing,spend})` exposes the same status and applies the gate when requested. No manifest bypasses configuration selection or paid opt-in. Caller must bind all scope values to the intended launch and call immediately before spawn; this does not resolve time-of-check/time-of-use races.

Resource freshness is checked against the local clock, which is not trusted time. Manifest author, host, auth, balance, billing, actual quotas, approval and issuer remain unauthenticated/unknown. No account inventory or live provider/host validation is performed. Actual experiments require separate authorization and the checked ingress and measurement provenance contracts; offline validation does not run an experiment.
