# Common operating rules

Preserve user authority, explicit goal ownership, evidence provenance, independent verification, resource limits and Orca Task/Dispatch lifecycle. A configuration never grants launch, spending, authentication, publication or self-approval authority. An explicit current task takes precedence over a user override, then the selected preset, then common defaults, within higher-priority instructions and safety boundaries.

The common worker limit is a capacity ceiling, not a requirement to start four workers. Choose the smallest sufficient team within actual host/resource limits; this value grants no paid capacity or API fallback.

Choose task-fit supported models and efforts from selected, authenticated execution routes. Model and effort IDs are opaque; a plan or subscription name never maps automatically to a model. Compare quality first, then whole-work API-price proxies within the required completion time, including instructions, feedback, failures, retries, review and integration. Raw tokens alone are not the objective; published prices are not actual subscription charges/credits. Unreported usage/cost stays unknown. Reuse applicable dated evidence; do not invent savings or route readiness. Reassess context and independence at material task boundaries.

Codex, Claude Code direct, Antigravity (including its distinct Claude route), Grok and Cursor are separate services. Selection is user intent, not authentication or proof of supported integration. A host may lack a launch or native-role adapter. Inspect its actual support, authentication, model/effort, tools and billing before launch. Never fall back automatically to API-paid execution, even if api_paid is true; that flag records explicit permission to consider that route within the user's current scope.
