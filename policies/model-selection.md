# Task-specific model selection

Active Orca Company routing uses the resolved Markdown configuration and
[model routing](../skills/company-orchestration/references/model-routing.md).
Use the [task candidate guide](../skills/company-orchestration/references/model-candidates.md)
and [evidence method](../skills/company-orchestration/references/model-evidence.md)
for current task-specific comparison. This document supplies no personal model
preferences, default provider ordering or authority over a running session.

Meet quality, user authority, tool and billing requirements first. Choose model ×
effort for the actual task, independent of CEO/head/lead/worker responsibility.
Compare whole-work API-price proxies, not raw tokens alone: include instructions,
feedback, failures, retries, verification and integration within the deadline.
Published rates/benchmarks are priors or estimates, not actual subscription charges
or local savings. Unknown usage stays unknown; no API spending is authorized here.

The LLM classifies task capability, coupling, decomposability and quality fit; the
packaged pure selector applies supported candidates, configuration and a declared
price basis. Comparable quality priors permit a cheaper start without compulsory
local A/B, not all-Terra or universal cheap-first. Complex coupled coding may need
Sol/Astra execution; separable work can split hard judgment from bounded production.
Small tasks avoid unnecessary tiers, and strong consultation needs real ambiguity,
conflict or repeated failure. Existing responsibility and approval boundaries hold.

Keep semantic profile requirements, independent verification and actual host
Task/Dispatch lifecycle intact. Read back requested versus effective settings.
A public benchmark, configuration document or installed file does not certify
provider authentication, live behavior or business outcomes. Keep personal
preferences and account observations in private configuration and run records.
